# СПБГАСУ Знакомства — запуск в @gasulvbot

Проект подготовлен для размещения на одном VPS. В Telegram он начнёт работать после запуска сервера, настройки домена и подключения бота. Токена, действующей базы пользователей и тестовых анкет в архиве нет.

## 1. Что нужно получить

- VPS с Ubuntu 24.04 LTS. Для начального небольшого запуска ориентир — 2 ГБ RAM, 2 vCPU и 20 ГБ SSD; это стартовая оценка, а не обещание конкретного числа пользователей.
- Домен или поддомен, например `dating.example.ru`. В DNS создайте A-запись `dating`, указывающую на IPv4 вашего VPS. Если используете AAAA, она тоже должна указывать на этот сервер.
- Открытые входящие порты 80 и 443 для сайта и 22 для вашего SSH-доступа. Порт приложения 3000 наружу не открывается.
- Доступ к @BotFather от владельца @gasulvbot. В `/mybots` выберите этого бота и получите его API Token. Вставьте токен непосредственно в серверный `.env`, не в переписку и не в браузерный код.

Для HTTPS домен должен указывать на VPS. Сертификат выпустит и будет обновлять Caddy. [Документация Caddy](https://caddyserver.com/docs/automatic-https).

## 2. Загрузить проект на сервер

Распакуйте архив на компьютере. Ниже `SERVER_IP` — IP вашего VPS, `root` — пример пользователя сервера. Если ваш провайдер выдал другое имя, используйте его.

На Mac в Терминале, из папки с распакованным проектом:

```bash
scp -r gasulvbot-miniapp root@SERVER_IP:/opt/gasulvbot
ssh root@SERVER_IP
```

Дальнейшие команды выполняются на VPS:

```bash
cd /opt/gasulvbot
```

Если загружаете через файловый менеджер/SFTP, положите содержимое проекта в `/opt/gasulvbot`. В этой папке должны лежать `compose.yaml`, `Dockerfile`, `index.html` и папка `server`.

## 3. Установить Docker на новом Ubuntu VPS

В проекте есть скрипт установки из официального репозитория Docker:

```bash
sudo bash deploy/install-docker.sh
```

Он предназначен для нового Ubuntu VPS. Другие ОС и серверы с конфликтующими пакетами настраиваются по [официальной инструкции Docker](https://docs.docker.com/engine/install/ubuntu/).

## 4. Заполнить конфигурацию

```bash
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
nano .env
```

Последняя команда открывает редактор. Впишите:

| Поле | Значение |
| --- | --- |
| `BOT_TOKEN` | API Token именно от @gasulvbot |
| `BOT_USERNAME` | `gasulvbot` |
| `PUBLIC_URL` | `https://ВАШ-ДОМЕН`, без пути |
| `APP_DOMAIN` | `ВАШ-ДОМЕН`, без `https://` |
| `WEBHOOK_SECRET` | Случайная строка, полученная через `openssl rand -hex 32` |
| `CONTACT_URL` | HTTPS-ссылка на ваш аккаунт поддержки/оператора |
| `ADMIN_TELEGRAM_IDS` | Ваш числовой Telegram ID; временно можно оставить пустым |

`APP_ENV=production` оставьте как есть. Пути `/app/data/...` — внутренние пути контейнера, менять их не нужно. `PUBLIC_URL` и `APP_DOMAIN` должны обозначать один и тот же домен.

Сохранить в nano: Ctrl+O, Enter, Ctrl+X.

## 5. Запустить приложение и базу

```bash
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail=80 app caddy
```

Первый запуск может занять несколько минут: скачиваются образы, собирается приложение и выпускается сертификат. База создаётся автоматически в постоянном томе `app_data`.

Откройте в обычном браузере:

```text
https://ВАШ-ДОМЕН/health
```

Должно появиться:

```json
{"ok":true}
```

Корень сайта в обычном браузере предложит открыть Telegram. Вход по произвольному имени или фальшивому Telegram ID отсутствует.

Если `/health` не открывается, проверьте DNS, входящие порты 80/443 и журнал Caddy. Затем переходите к подключению бота.

## 6. Подключить @gasulvbot

В папке проекта на VPS:

```bash
sudo docker compose exec app node server/setup-bot.mjs
sudo docker compose exec app node server/setup-bot.mjs --check
```

Скрипт проверит, что токен принадлежит @gasulvbot, настроит кнопку «Знакомства ♥», команды и защищённый webhook. Он заменит прежние команды, кнопку меню и webhook этого бота. Существующие сценарии другого сервера бота нужно переносить отдельно.

В Telegram отправьте @gasulvbot `/start` и нажмите кнопку приложения. Кнопка меню тоже открывает его. [Официальная документация Telegram о кнопке меню](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button).

Для большой кнопки приложения в профиле бота откройте @BotFather → `/mybots` → @gasulvbot → настройки Main Mini App / Configure Mini App. Включите Main Mini App и укажите тот же HTTPS-адрес. После этого работает ссылка:

```text
https://t.me/gasulvbot?startapp
```

[Официальная документация Main Mini App](https://core.telegram.org/bots/features#mini-apps).

## 7. Получить доступ администратора

Отправьте своему боту `/id` — он покажет ваш Telegram ID. Его также видно в настройках приложения.

В `.env` впишите это число в `ADMIN_TELEGRAM_IDS`. Для нескольких администраторов используйте запятую. После изменения:

```bash
sudo docker compose up -d
```

Закройте и снова откройте приложение. В настройках появится «Модерация»: можно читать жалобы, отмечать их обработанными и ограничивать/возвращать доступ пользователя.

## 8. Проверить вдвоём

Используйте два настоящих Telegram-аккаунта, каждому должно быть 18+:

1. Оба отправляют боту `/start`, открывают приложение и заполняют анкеты со своими фото.
2. Первый лайкает второго. У второго появляется уведомление и входящий лайк.
3. Второй отвечает лайком. У обоих появляется мэтч, автоматически создаётся один общий чат.
4. Отправьте сообщения в обе стороны. В открытом приложении они появляются через соединение событий; при сбоях есть переподключение и периодическая синхронизация.
5. Закройте приложение одного аккаунта и отправьте сообщение с другого: бот должен прислать уведомление, если сообщения разрешены.
6. Проверьте подписку, счётчики, редактирование анкеты, скрытие профиля и перезапуск приложения.

Первоначально лента будет пустой. В неё попадут только реальные люди после заполнения анкеты. Действующие чаты доступны и при скрытой анкете; блокировка прекращает взаимодействия и удаляет общий чат.

## 9. Где хранится база и как делать копии

SQLite в режиме WAL хранится в Docker-томе `app_data`. В базе находятся анкеты, сжатые JPEG-фото, лайки, подписки, пары, сообщения, уведомления и серверные сессии. Перезапуск и пересборка контейнера не стирают этот том.

**Не выполняйте `docker compose down -v`: параметр `-v` удаляет постоянные тома, включая базу.**

Контейнер `backup` делает копию сразу после запуска и далее каждые 24 часа. Он сохраняет последние 7 копий и проверяет их целостность. Копии на том же VPS помогают при ошибках приложения, но не при потере сервера: переносите их на отдельное хранилище.

Копия вручную и просмотр списка:

```bash
sudo docker compose exec app node server/backup.mjs
sudo docker compose exec app ls -lh /app/data/backups
```

Выгрузить каталог копий на VPS, затем скачать через SFTP:

```bash
sudo docker compose cp app:/app/data/backups ./backups
```

Для восстановления положите выбранную копию в папку проекта как `restore.sqlite`. Затем:

```bash
sudo docker compose stop app backup
sudo docker compose run --rm --no-deps -v "$PWD/restore.sqlite:/restore.sqlite:ro" --entrypoint node app server/restore.mjs /restore.sqlite
sudo docker compose up -d
```

Скрипт сначала проверит копию и сохранит текущую базу с именем `pre-restore-...`, затем восстановит выбранное состояние. Восстановление вернёт всё к моменту создания копии. Предварительные копии `pre-restore-...` не входят в автоматическую ротацию — их срок хранения выбираете вы.

## 10. Обновления и диагностика

После загрузки обновлённых исходников на VPS:

```bash
sudo docker compose exec app node server/backup.mjs
sudo docker compose up -d --build
```

Не перезаписывайте рабочий `.env` шаблоном при обновлении. При смене домена или webhook-секрета повторите `setup-bot.mjs` и обновите адрес Main Mini App в @BotFather.

Диагностика:

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 app
sudo docker compose logs --tail=100 caddy
sudo docker compose logs --tail=100 backup
sudo docker compose exec app node server/setup-bot.mjs --check
```

| Симптом | Что проверить |
| --- | --- |
| Нет HTTPS | DNS, A/AAAA, порты 80/443, журнал Caddy |
| Бот не отвечает на `/start` | Webhook, токен, секрет, `--check`, не работает ли прежний сервер бота |
| Нет уведомлений от бота | `/start` или разрешение сообщений, настройки, не заблокирован ли бот |
| Вход истёк | Закрыть и открыть Mini App заново |
| Нет анкет | Другие люди ещё не зарегистрировались, фильтры, скрытые/пропущенные анкеты |
| Нет «Модерации» | Ваш числовой ID в `.env`, пересоздание контейнера и повторное открытие |

## 11. Что подготовлено и что ещё проверять

Реализованы проверка `initData` на сервере, серверные сессии, проверка прав на чат и фото, ограничения частоты запросов, атомарное создание пары, защита от дублей сообщений, очередь уведомлений с повторными попытками, блокировки, жалобы и удаление аккаунта. [Проверка данных Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

Возраст и учёба указываются самим пользователем; официальная проверка статуса студента не реализована. Не заявляйте, что регистрация автоматически подтверждает обучение в СПБГАСУ.

Страница данных описывает фактическое хранение. Перед публичным набором пользователей впишите реальные контакты оператора, условия сервиса и срок хранения копий. Жалобы после удаления аккаунта сохраняются с отвязанным ID; текст причины может содержать сведения, которые сообщил автор жалобы.

Используйте один экземпляр приложения и один локальный постоянный том базы. Если понадобится несколько серверов, SQLite и локальное соединение событий следует заменить общей БД и механизмом доставки событий между экземплярами.

В этой сессии проверены 17 автоматических сценариев, включая HTTP API, подпись Telegram, права участников, обновления, отсутствие дублей, фильтры анкеты и восстановление базы. Реальный токен не использовался. Docker, HTTPS и работа на устройствах Telegram проверяются после размещения: VPS ещё не создан, конфигурация бота не изменена.

Разработчику для повторения проверок нужен Node.js 24:

```bash
npm test
```

Проект использует стандартные модули Node.js и встроенный SQLite, установка npm-зависимостей не требуется.
