# СПБГАСУ Знакомства: GitHub → Render → Telegram

Это готовый проект Telegram Mini App с сервером Node.js 24 и SQLite. GitHub хранит код; Render запускает сервер и хранит базу; Telegram открывает интерфейс и подтверждает пользователя.

**Размещение ещё не выполнено.** Нужны ваш GitHub, аккаунт Render и токен вашего бота. Ниже — полный порядок запуска без VPS и своего домена.

## 1. Что исправлено и подготовлено

- Исправлен повреждённый `</script>` в index.html, из-за которого интерфейс не запускался.
- Добавлен render.yaml: сервер Docker, проверка /health, постоянный диск /app/data на 1 ГБ.
- Адрес Render автоматически используется сервером для входа и настройки бота.
- Команды npm работают с переменными хостинга без обязательного файла .env.
- Добавлены автоматические тесты GitHub Actions и проверки новых изменений.

Анкеты, фото и сообщения сохраняются в SQLite. GitHub Pages не запускает этот сервер. Не выбирайте Static Site для этого проекта.

## 2. Подготовьте бота

1. Откройте настоящего [@BotFather](https://t.me/BotFather) в Telegram.
2. Если бот уже есть: /mybots → выберите бота → API Token. Если нет: /newbot → имя → свободный username, заканчивающийся на bot.
3. Сохраните токен приватно. Не вставляйте его в GitHub, исходники или переписку.
4. Запишите username без @. Значение gasulvbot подходит только если это ваш бот и токен принадлежит ему.
5. Откройте Terminal на Mac и выполните:

```sh
openssl rand -hex 32
```

Скопируйте результат: это WEBHOOK_SECRET. Создайте собственный случайный секрет, не используйте пример из инструкции.

## 3. Создайте репозиторий GitHub

Проще всего загрузить через GitHub Desktop: он добавит также скрытую папку .github с проверками.

1. Установите [GitHub Desktop](https://desktop.github.com/) и войдите в свой аккаунт.
2. File → New Repository. Name: spbgasu-dating-app. Выберите удобную папку; Create Repository.
3. В Finder откройте созданный репозиторий и скопируйте в него **содержимое подготовленной папки spbgasu_dating_app**, а не саму папку целиком. В корне должны лежать index.html, package.json, Dockerfile, render.yaml, server и tests.
4. Нажмите Cmd+Shift+. в Finder, чтобы показать скрытые файлы. Перенесите .github, .gitignore, .dockerignore, .env.example. Не заменяйте и не копируйте .git.
5. В GitHub Desktop проверьте список изменений. Файла .env, токена и пользовательской базы там быть не должно.
6. Summary: Initial app. Commit to main → Publish repository. Оставьте Keep this code private включённым → Publish Repository.
7. View on GitHub: убедитесь, что render.yaml находится в корне. Во вкладке Actions дождитесь зелёного Tests.

Альтернатива через сайт: [создать репозиторий](https://github.com/new) → Private → Create repository → uploading an existing file. Загрузите содержимое папки, сохраняя server, tests, deploy и .github. Проверьте скрытые файлы отдельно: браузерная загрузка может их пропустить. Архив ZIP внутрь репозитория загружать не нужно.

## 4. Запустите сервер на Render

**Этот вариант платный:** постоянный диск доступен у платных сервисов Render. Перед созданием проверьте итоговую стоимость сервера и диска в форме Render. Бесплатный сервис без диска будет терять локальную базу при перезапуске/публикации.

1. Откройте [Render](https://dashboard.render.com/) и войдите через GitHub.
2. Разрешите Render доступ к вашему репозиторию.
3. New → Blueprint → выберите spbgasu-dating-app. В качестве файла настроек используйте render.yaml из корня репозитория.
4. Заполните три значения:

| Переменная | Что вставить |
|---|---|
| BOT_TOKEN | Токен вашего бота из BotFather |
| BOT_USERNAME | Username этого бота без @ |
| WEBHOOK_SECRET | Результат openssl rand -hex 32 |

5. Проверьте: Web Service, Docker, платный план, один экземпляр, диск /app/data размером 1 ГБ. Подтвердите создание только после проверки цены.
6. Дождитесь Live. Скопируйте HTTPS-адрес сервиса, например https://spbgasu-dating-xxxx.onrender.com. Это пример: используйте фактический адрес из Render.
7. Откройте адрес с /health в конце. Ожидается:

```json
{"ok":true}
```

PUBLIC_URL заполнять не требуется: сервер берёт RENDER_EXTERNAL_URL автоматически. APP_DOMAIN и Caddy на Render не нужны; compose.yaml предназначен для альтернативного запуска на VPS.

Если добавите свой домен позже, задайте PUBLIC_URL=https://ваш-домен без пути, затем повторите настройку бота.

## 5. Подключите Telegram

1. В Render откройте созданный сервис → Shell.
2. Выполните:

```sh
npm run telegram:setup
```

Команда проверяет токен и доступность сайта, ставит кнопку «Знакомства ♥», команды бота и webhook. Токен повторно вводить не нужно: он уже в переменных сервиса.

3. Затем:

```sh
npm run telegram:check
```

Ожидается: ваш бот, webhook с вашим адресом и /telegram/webhook, menu типа web_app с вашим HTTPS-адресом, lastError: null. Если ошибка старая, отправьте боту /start и проверьте ещё раз.

4. В BotFather: /mybots → ваш бот → Bot Settings → Configure Mini App (или Main Mini App) → Enable Mini App. Укажите HTTPS-адрес Render. Названия пунктов могут отличаться между версиями Telegram. Это добавляет кнопку запуска на странице бота; кнопка меню уже настроена командой выше.
5. Откройте своего бота в Telegram, нажмите Start или отправьте /start → «Открыть»/«Знакомства ♥».

Не вставляйте адрес /health или /telegram/webhook в BotFather: нужен только корневой HTTPS-адрес приложения.

## 6. Проверьте реальную работу

1. Откройте через Telegram и создайте свою анкету, добавив фото и согласие.
2. Со второго Telegram-аккаунта создайте вторую анкету.
3. Убедитесь, что анкеты видят друг друга. Поставьте лайки с обеих сторон: должен появиться матч и чат.
4. Отправьте сообщение и проверьте получение на втором аккаунте.
5. Закройте и откройте приложение: анкета и чат должны сохраниться.
6. Выполните Manual Deploy на Render и повторите проверку сохранности.
7. Проверьте жалобу, блокировку и удаление своей тестовой анкеты.

Пустая лента сразу после запуска нормальна: готовых тестовых пользователей в базе нет. Вход выполняется через Telegram; обычное открытие URL в браузере не заменяет вход.

Для модерации: отправьте боту /id. В Render → Environment добавьте ADMIN_TELEGRAM_IDS со своим числовым ID (несколько — через запятую) и примените изменения. Повторно откройте Mini App. CONTACT_URL можно задать как HTTPS-ссылку на ваш контакт поддержки.

## 7. Обновления и резервные копии

Меняйте файлы в папке репозитория → Commit → Push в GitHub Desktop. Render может автоматически публиковать изменения; проверяйте его Events и результат GitHub Actions. Для ручной публикации: Manual Deploy → Deploy latest commit. Во время публикации сервиса с диском возможна короткая недоступность.

Перед существенным обновлением выполните в Render Shell:

```sh
npm run backup
```

Копия SQLite (включая фото) появится в /app/data/backups. Хранятся последние 7 копий. **Render Blueprint не запускает ежедневный backup-контейнер из compose.yaml**: в этом варианте команда резервного копирования ручная. Сохраняйте копии также вне сервиса; копия на том же диске не защитит от удаления диска. Для автоматического ежедневного копирования используйте описанный в ЗАПУСК_В_TELEGRAM.md вариант VPS или отдельно настройте расписание и внешнее хранение.

Не удаляйте Render-сервис/диск без внешней копии. На VPS не выполняйте docker compose down -v.

## 8. Если не работает

| Симптом | Проверка |
|---|---|
| Deploy failed | Logs: BOT_TOKEN, WEBHOOK_SECRET, Dockerfile в корне; не выбран Static Site |
| SQLITE_CANTOPEN / permission denied | Диск подключён именно к /app/data; DB_PATH=/app/data/app.sqlite; проверьте права в Shell |
| Сервер жив, интерфейс пустой | Убедитесь, что загружен исправленный index.html; закройте и откройте Mini App |
| Токен принадлежит другому боту | BOT_USERNAME должен соответствовать токену, без @ |
| Бот не отвечает на /start | npm run telegram:setup, затем telegram:check; webhook должен вести на текущий сервис |
| «Запрос с другого сайта запрещён» | Проверьте PUBLIC_URL: удалите старое значение или задайте фактический домен; повторите настройку бота |
| «Откройте из Telegram» | Запускайте кнопкой бота/Main Mini App; ссылка в браузере не передаёт подписанные данные Telegram |
| Анкеты пропали после deploy | Проверьте постоянный диск и DB_PATH; восстановление требует ранее сохранённой копии |
| Нет людей | Нужны другие зарегистрированные пользователи и подходящие фильтры |

Если просите помощь, достаточно текста ошибки из Logs, адреса сервиса и результата telegram:check. Токен и WEBHOOK_SECRET не отправляйте.
